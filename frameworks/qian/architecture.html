    Qian 与 Kun 的关系：Kun 是底座 SDK，Qian 内核自成一层
    插件模型：kind × role × distribution 三轴，平台自带能力也是插件，第三方代码永不进共享进程
    内核边界与 S1 服务拆分：内核只留契约、强制执行点与注册表；S1 共 5 个可部署服务 + 18 个系统插件
    数据库与租户隔离：PostgreSQL 唯一一等库；默认共享库 + RLS；schema-per-service
    身份与 SSO：基于 OpenIddict 自建 qian.identity 作平台唯一 issuer，外部 IdP 一律做成连接器插件
    鉴权模型：Kun 只加判定端口，Qian 自建权限引擎；权限不进令牌；UI/API/MCP 唯一判定入口
    配置中心：Apollo 作 L1 共享组件，自研 AOT 友好的 .NET provider；只存非敏感配置与密钥引用；租户级配置不进 Apollo
    事件与消息：RabbitMQ 上 K3s；修复 Outbox 丢消息与至少一次语义；事件信封对齐［下游智能体平台］契约
    审计：只留一套——命令级哈希链落 PostgreSQL + 实体级同事务写入；actor 含 agent
    网关分层：Traefik（北向入口）→ qian.gateway（Kun.Gateway 加固，业务 API 边界）；Higress 只管模型与 MCP 流量
    元数据与动态数据层：元数据驱动运行时为主；动态表走「物理主表 + JSON 列」混合存储、不走 EF 模型；统一 Filter AST；正式 Schema Migrator；代码生成退化为可选薄壳
    流程引擎：自研 .NET 轻量审批内核；简单/标准流程合并为一套 JSON 定义；S2 只做节点树视图设计器
    前端与［前端框架］：React 19 + Vite + Tailwind v4 + Base UI + shadcn 源码自有化；六层分层；一套表单/表格/弹层引擎；Module Federation 2 外壳
    应用市场形态：应用 = 插件包（bundle）；template / managed 两种分发；S1 就定下包格式、升级与冲突处理、权益 API
    模型服务网关：并入团队现有 Higress / MaaS 基础设施；GPUStack 作 OpenAI 兼容上游 + Provider Adapter；不自写模型代理；不把 SSO 交给 Higress
    与［下游智能体平台］的边界：Qian = 能力提供方 + 业务主数据权威；［下游智能体平台］ = Agent 运行时 + AI 资产控制面；Qian 不写任何 Agent loop
    部署：沿用现有 K3s / ArgoCD / Kustomize / Harbor 约定；Qian 独立命名空间 + 专属 PG/Redis；不以 per-tenant namespace 为默认
    阶段切分与 S1 范围：S1 技术底座 → S2 低代码构建 → S3 面向客户 → S4 AI 原生 Agent 平台；每阶段有可验收的退出标准
    库优先（Library-first）：每个 Qian 系统组件首先是可独立安装使用的 NuGet 包，其次才经清单成为插件；插件 = 库 + 清单

    #Qian 框架架构

    状态：规划稿（2026-11-17）。「已有」指已经实现、随框架库迁入本仓库的部分。

    2026-11-19 补：拖拽设计器缓做、最终用户的入口是 Agent 平台、人审两道都必审已定（2026-11-19 平台级裁定 P32、P24、P28），见第 2、3、6 节。

    #1 边界

    Qian 负责界面与交互。它不负责：

    • 业务数据与权限的判定，那在 Kun。界面里看不到的能力，后端同样拒绝，前端的隐藏只是体验，不是安全措施。
    • 智能体的推理，那在 SanYuanAgent。Qian 展示它的过程与结果。

    Qian 只经公开的接口与契约访问后端。

    #2 分层与依赖方向

    • 箭头表示「被上面依赖」。下层不得引用上层；同一层的包互不依赖，例外要写进决策记录。
    • 设计令牌和界面契约在最底层，不依赖任何别的包。
    • 允许的依赖写在一张矩阵里，是唯一的依据。新建一个包，先在矩阵里登记；没登记的包什么都不许引用。
    • TypeScript 运行时与前端插件开发包在组件库之上：组件库不得反过来引用它们。
    • 图表、代码编辑器、控件、渲染器、设计器（表单、列表、流程、门户）、移动端、面向智能体的界面等包已经在矩阵里留了位置，还没有实现。渲染器的包名已定为 @cavailab/qian-renderer，放由 Schema 驱动的表单、列表、详情渲染器与动作执行器，与管插件树的 TypeScript 运行时是两回事。面向智能体的界面在矩阵里只允许依赖基础组件与开发包。
    • 设计器缓做（已定，2026-11-19）：先让智能体写，设计器以后作为第二种编写方式。矩阵里给它留的位置照旧；什么时候做，待定，见平台总览的路线第 5 节。

    #3 应用外壳

    本节描述 Kun 仓库中的现有应用外壳。它使用 Qian 发布的组件包，承载各应用的页面。

    本次迁移按 Qian 0.2.1 的包、标签和外壳源码归档验收。业务预发继续运行原版外壳与远程模块，保留现有数据。外壳迁移裁定 P42

    匠心工业智能体平台的 Web 和桌面端采用 DSH 客户端。旧外壳源码以后的用途、Qian 是否再发新版，以及产品登录、租户、策略和审计由哪个后端提供，仍待决定。产品裁定 P38

    • 运行时配置。 外壳启动时从同源地址读配置，同一份构建产物可以部署到不同环境。
    • 会话。 浏览器里不放令牌。登录之后会话由网关持有，前端只带会话 Cookie；会话过期有统一的处理。
    • 启动聚合。 外壳启动时一次取回当前用户、租户、权限与可用的能力。
    • 能力导航。 菜单由后端的能力与权限生成，映射到路由。
    • 租户切换、站内信、偏好设置、兜底页。

    外壳本身是一棵插件树。前端有一个与后端同语义的运行时：服务带范围，注册是可以撤销的副作用，租户范围里的注册遮蔽全局项。

    #4 微前端与界面表面

    业务页面不打进外壳，它们是远程模块，由外壳按需加载。

    • 一个插件的界面表面是一份界面清单：它暴露哪些页面、控件、设置卡。
    • 外壳读清单，把页面挂进路由和菜单，把控件挂进插槽。
    • 远程模块经桥接接口调用后端能力，不自己拼请求地址，也不自己处理认证。
    • 第三方的界面按信任等级隔离运行。这一条在组件模型的规格里已经规定，随第三方组件开放时落地。

    #5 由 Schema 驱动的界面

    表单、列表、控件清单都有 JSON Schema 草案，并由它生成类型。

    • 表单由 Schema 渲染：字段、联动、校验、脱敏规则都在 Schema 里。
    • 列表同理：列、筛选、排序、操作由 Schema 描述。
    • 界面契约是 Qian 与 Kun、SanYuanAgent 共用的数据约定。

    这是自然语言构建在界面上的落点。智能体要做一个录入页面，产出的是一份表单 Schema；人预览、批准之后，Qian 把它渲染出来。智能体不生成前端代码，也就不需要为它生成的代码做安全审查。

    #6 面向智能体的界面

    下表记录 Qian 冻结前为 Agent 平台拟定的界面。产品的角色与形态见平台总览的角色与产品形态第 4 节。

    界面作用
    意图输入人用自然语言提出要做的事
    过程展示把智能体运行的事件流展示出来：步骤、工具调用、产物、最终回答
    预览与批准智能体生成的界面与变更，先预览，人批准后发布
    审核收件箱起步出站、入站两道都必审（已定）。我的 Agent 要发出去的内容，在这里确认、修改后确认或撤回；发给我的 Agent 的协同消息，在这里批准、修改后批准、驳回或转交
    对话里的确认卡Agent 要改数据或往外发内容时，在对话里出一张确认卡，人点了才执行
    我的 Agent查看和管理自己名下的 Agent、它们的授权范围和挂在上面的组件
    线程视图一件协同事务里人与 Agent 的全部往来

    「发出去」包括三类：发给别的 Agent、发给别人、写外部系统（已定）。发给别的 Agent 的消息走平台的信箱；另外两类不经信箱，在对话里出确认卡（提议）。见平台总览的 Agent 协同第 4.2 节。

    #8 版本与发布

    • packages/qian/* 的 8 个包固定同一个版本号；TypeScript 运行时与前端插件开发包各自定版本。
    • 1.0 之前每个次版本都可能有破坏性变更；1.0 之后只在主版本破坏，废弃的接口至少保留一个次版本并给出迁移说明。
    • 改了包的公开行为，在 PR 里登记变更级别，合并后由发布流程统一出版本。

    #9 待定

    归属已定的几项不再列在这里：TypeScript 运行时与前端插件开发包随本仓库；命令行、应用外壳与平台组件自带的界面留在后端仓库。见迁移文档第 2 节。

    包的可见性与发布位置作用域按 @cavailab：包发在 GitHub Packages，它要求包的作用域与仓库所有者同名。包是否公开、要不要另发公共的 npm 包源，待定，见迁移文档第 8 节
