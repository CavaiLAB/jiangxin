    Qian 与 Kun 的关系：Kun 是底座 SDK，Qian 内核自成一层
    插件模型：kind × role × distribution 三轴，平台自带能力也是插件，第三方代码永不进共享进程
    内核边界与 S1 服务拆分：内核只留契约、强制执行点与注册表；S1 共 5 个可部署服务 + 18 个系统插件
    数据库与租户隔离：PostgreSQL 唯一一等库；默认共享库 + RLS；schema-per-service
    身份与 SSO：基于 OpenIddict 自建 qian.identity 作平台唯一 issuer，外部 IdP 一律做成连接器插件
    鉴权模型：Kun 只加判定端口，Qian 自建权限引擎；权限不进令牌；UI/API/MCP 唯一判定入口
    配置中心：Apollo 作 L1 共享组件，自研 AOT 友好的 .NET provider；只存非敏感配置与密钥引用；租户级配置不进 Apollo
    事件与消息：RabbitMQ 上 K3s；修复 Outbox 丢消息与至少一次语义；事件信封对齐［下游智能体平台］契约
    审计：只留一套——命令级哈希链落 PostgreSQL + 实体级同事务写入；actor 含 agent
    网关分层：Traefik（北向入口）→ qian.gateway（Kun.Gateway 加固，业务 API 边界）；Higress 只管模型与 MCP 流量
    元数据与动态数据层：元数据驱动运行时为主；动态表走「物理主表 + JSON 列」混合存储、不走 EF 模型；统一 Filter AST；正式 Schema Migrator；代码生成退化为可选薄壳
    流程引擎：自研 .NET 轻量审批内核；简单/标准流程合并为一套 JSON 定义；S2 只做节点树视图设计器
    前端与［前端框架］：React 19 + Vite + Tailwind v4 + Base UI + shadcn 源码自有化；六层分层；一套表单/表格/弹层引擎；Module Federation 2 外壳
    应用市场形态：应用 = 插件包（bundle）；template / managed 两种分发；S1 就定下包格式、升级与冲突处理、权益 API
    模型服务网关：并入团队现有 Higress / MaaS 基础设施；GPUStack 作 OpenAI 兼容上游 + Provider Adapter；不自写模型代理；不把 SSO 交给 Higress
    与［下游智能体平台］的边界：Qian = 能力提供方 + 业务主数据权威；［下游智能体平台］ = Agent 运行时 + AI 资产控制面；Qian 不写任何 Agent loop
    部署：沿用现有 K3s / ArgoCD / Kustomize / Harbor 约定；Qian 独立命名空间 + 专属 PG/Redis；不以 per-tenant namespace 为默认

    库优先（Library-first）：每个 Qian 系统组件首先是可独立安装使用的 NuGet 包，其次才经清单成为插件；插件 = 库 + 清单

    #ADR-013 前端与［前端框架］

    本文保留当时的决策。方括号中的能力描述用于标出整理时替换的引擎或下游名称。

    2026-10-07 经 ADR-021 修订：D13.18 文档站的覆盖范围从「Qian 平台与［前端框架］组件」扩为整个产品族，底座框架 Kun 以镜像小节进入第 3 部分（规则见 specs/docs-site.md §2b）。

    2026-11-17 经 ADR-023 修订。 前端框架由［前端框架］更名为 qian（D23.17、D23.18）：8 个包改叫 @idadawn/qian-<原名>，UI 清单键 engines.yue 改为 engines.qian，许可证改为 MIT。更名排在合并阶段 3 的最后一批（S1-YUE-022），落地之前本文与代码里的［前端框架］字面不变。

    #1 背景与问题（Context）

    参考平台前端是「两套并存」的反面教材：Vue 3 + 开源后台模板内核之上叠加另一套 UI 库封装与第三方表格，弹窗、表单、表格、Tree、Loading 都有两到三套实现；去重后组件与设计器全集约 251 条目，其中真正的设计器 8 个（基线 U §0 第 1 条）。控件三态（编辑 / 只读 / 单元格）各自硬编码，新增控件改三处；列表 PC / 移动两份完整配置（基线 F §6 第 7/9 条）。

    ［下游智能体平台］前端有好的工程规范与令牌思路（React 19 + TypeScript + Vite + Tailwind v4 + shadcn，console 版令牌架构，工程门禁），但没有组件库：［下游界面工具包］ 是 29 行占位，产品里真正在用的 shadcn 组件只有 Toaster，数据密集型控件全部缺失，Base UI 只用了 Dialog 一个原语（基线 U §0 第 2 条、§7.2）。shadcn 自 2026-07 起新项目默认 Base UI（基线 U §4）。前端插件化方面，Module Federation 2 的 registerRemotes / loadRemote 允许加载启动后才发现的远程，但 MF 零隔离，只能给可信插件（基线 P §9.1）。三条安全硬线：不用 eval 执行租户脚本；令牌不进 URL / iframe；前端权限裁剪只是体验层（基线 U §0 第 6 条）。

    #2 决策（Decision）

    • D13.1 技术栈【文档工具部分已由 ADR-022 修订为统一 Rspress；下文保留原决策】（路线 A，沿用［下游智能体平台］已验证组合）：React 19 + TypeScript + Vite + Tailwind v4 + Base UI + shadcn 源码自有化；Zustand + TanStack Query；react-router 7；i18next；Vitest + Playwright + axe；Lighthouse 预算；Changesets 发包；Storybook 10；API client 从 Kun OpenAPI 生成（orval / openapi-typescript）+ 契约快照测试。
    • D13.2 ［前端框架］六层 + 横切：［设计令牌包］（primitive → semantic → component 三层令牌、明暗两态）→ ［基础组件包］（约 30 个基础组件，Base UI + shadcn 自有化）→ 后台通用层（［前端外壳包］ AppShell、［数据组件包］ DataTable 基于 TanStack Table v9 + Virtual、［表单组件包］ Field + SchemaForm 基于 react-hook-form + Ajv、［图表组件］ ECharts 6、［代码编辑组件］ Monaco + CodeMirror 6；Upload 分片 + MD5；Tree / Cascader / 日期）→ ［业务组件包］ 业务选择器（组织 / 用户 / 角色 / 岗位 / 字典 / 接口选择）→ ［页面渲染运行时］ + ［设计器控件］ 低代码运行时与物料 → ［各类设计器组件］；横切 ［前端 SDK 包］（注册表 API、PlatformClient、拦截器链、i18n、mock）、［智能体交互组件］（S4）、［移动端组件］（S2 可选 / S3）。依赖方向严格自下而上，用 eslint-plugin-boundaries / dependency-cruiser 写死进 CI。
    • D13.3 只保留一套表单 / 表格 / 弹层引擎贯穿 S1 后台 CRUD 与 S2 低代码运行时；业务组件只做叶子，不得新建引擎。
    • D13.4 外壳：［前端外壳包］ + Module Federation 2 运行时加载（S1 必做）+ 带版本号的插槽注册表（qian.shell.nav/v1 等，破坏性变更开 v2 并给弃用窗口）；共享依赖 react / react-dom / @qian/yue / @qian/plugin-sdk 设 singleton；清单声明 engines.yue；［前端框架］严格 SemVer 且主版本升级有双版本并存期；只加载「本租户已启用 × 当前页面用得到」的贡献；宿主与插件之间走带作用域校验的桥接 API，插件 UI 消息视为不可信输入。
    • D13.5 不可信 UI：第三方首选 Worker + 远程渲染（插件只产出受约束的 UI 描述，组件实现只在宿主），需要完整自由度的走 iframe + 受限 CSP（CSP 由清单生成）；S3 对外开放时必做；第三方不可信 UI 直接 MF 挂载不做。
    • D13.6 控件注册表与［前端框架］组件 props 的 JSON Schema 机器可读：registerWidget(type, {meta, Runtime, Designer, toSearchControl, toCellRenderer})，meta 含 props JSON Schema、valueType、devices[]、能力位、默认运算符、authAware；一份注册表同时作设计器左栏与 GET /registry/widgets；设计器、远程渲染白名单、S4 Agent 生成 UI 共用一份契约。
    • D13.7 Base UI 验证门（Q12）：S1 首迭代对 Menu / Select / Combobox / Tabs / Tooltip / Tree 做键盘与可访问性覆盖验证；通过则锁定，不通过则整体切 Radix；不混用；接受自建数据密集组件的交付风险。
    • D13.8 移动端（Q13）：S2 只做 PC 响应式，预留端覆盖——一份 schema + device 维度覆盖，物料端支持矩阵显式降级；H5 / PWA 渲染器 S3 可选；小程序原生渲染本期不纳入。
    • D13.9 后台壳（Q37）：统一一个壳，按「平台控制台 / 应用」上下文切换，与插件外壳模型一致；不采用三面新窗口。
    • D13.10 布局与偏好（Q38）：S1 单一侧栏布局；多布局模式与偏好抽屉 S3 可选。
    • D13.11 富文本 / Markdown 编辑器（Q39）：五份调研均未覆盖，S2 前补一次选型调研后再排期。
    • D13.12 分发渠道（Q41）：私有 npm 为主——GitHub Packages，scope @idadawn，包名 ［前端包名］，文档中的 ［前端包名］ 是简称（2026-10-09 产品负责人拍板，见 §9）；shadcn 私有 registry + MCP Server 面向 ISV 与 Agent，S3 可选、S4 必做。
    • D13.13 令牌：三层结构 S1 必做；DTCG 格式导出 S1 可选；命名禁同名异义，状态色成对，WCAG AA 对比度单测进 CI；data-theme / data-brand 由服务端按租户下发，插件只引用语义令牌。实现落点（S1-YUE-004，PR idadawn/qian#32）：［设计令牌包］ 的 registry.json 定义三层令牌，生成 src/index.css（语义层在 html.dark, html[data-theme="dark"] 下重定义）与首帧脚本 theme-init.js；对比度与同名异义由 tokens.test.ts 与 check-tokens.mjs 守住；文档站经 S1-DOCS-004 改用同一包（S1-DEC-019 R72）。
    • D13.14 联动与脚本三层：声明式动作 → 可序列化表达式 DSL → QuickJS 沙箱脚本（白名单 API、超时、内存上限、不暴露令牌）；禁 eval / new Function。
    • D13.15 其他选型：dnd-kit（包一层抽象）；@xyflow/react 12（S3 自由画布）；react-grid-layout；Univer 开源核心（排除 Pro 与商业包，xlsx 导出放后端）；pdfme；quickjs-emscripten；不用 Formily / amis / lowcode-engine / bpmn-js。
    • D13.16 安全硬线：不用 eval 执行租户脚本；令牌不进 URL / iframe（一次性票据或 postMessage 握手）；前端权限裁剪只是体验层，鉴权在服务端；不在前端持有加密密钥；不持久化 token / 锁屏密码。
    • D13.17 为 S4 预留：机器可读 manifest；带版本的 Schema 与校验器（Agent 生成物走同一校验再落库）；客户端动作 / 导航 / 命令注册表（名称、参数 JSON Schema、权限、人话描述）；SSE 事件 JSON Schema 为唯一真相源生成 TS。
    • D13.18 文档站（2026-10-07 产品负责人确认）【经 ADR-022 收敛为唯一文档与演示体系，插件默认行为需按其验收补齐】：Rspress 2.0（MDX、React、与 Rslib 同属 Rsbuild 家族）作为 Qian 平台、［前端框架］组件与底座框架 Kun（镜像小节，ADR-021）的使用文档站；开启 llms 输出 llms.txt / llms-full.txt 与每页 Markdown（SSG-MD），供知识库与 Agent 读取；@rspress/plugin-preview / plugin-playground / plugin-api-docgen / plugin-typedoc 承担组件活演示与 API 表；.NET 包 API 参考用 DocFX，平台 OpenAPI 用 Scalar；文档源放在各组件文件夹（README 契约见 ADR-020 D20.9），构建前汇总进站点；站内「问 AI」S2 用自有模型网关（ADR-015）与［下游智能体平台］（ADR-016）实现，不购买 SaaS。信息架构（七个部分）、组件页模板与 frontmatter 规范见 docs/prd/specs/docs-site.md。备选 Docusaurus 3.x；不选 dumi / VitePress / MkDocs（分别因绑定 umi、无 MDX）。

    #3 理由（Rationale）

    • 两套体系并存是参考平台最大的前端债务；一套引擎是防复燃的唯一手段（基线 U §0 第 3 条）。
    • Base UI 与 shadcn 自有化让组件源码在自己仓库，许可与供应链可控；数据密集组件在 headless 的 TanStack 上自建，避免 AG Grid Enterprise 式的许可陷阱（基线 U §4）。
    • MF2 是「租户开通后才出现的插件 UI」唯一成熟的运行时加载方案；版本化插槽借鉴 Backstage 扩展点与 Grafana 静态声明（基线 P §9.1）。
    • 统一一个壳与插件外壳模型一致，三面新窗口会使路由与状态割裂。

    #4 备选方案与放弃原因（Alternatives）

    • antd v6 二次封装：只适合「S2 交付压力极大」时限平台控制台域使用并约定迁移期限；Q12 裁决接受路线 A 风险，不引入第二体系。放弃（保留为应急备选，需另行决策）。
    • Formily / amis / lowcode-engine：停滞或自带整套 UI 与状态体系。放弃。
    • bpmn-js：许可证水印要求。放弃。
    • 两套元数据（PC / 移动各一份）：参考平台反例。放弃。

    #2026-10-09 Base UI 验证门：通过，锁定 Base UI（S1-YUE-003）

    结论：路线 A 成立。锁定 @base-ui/react 1.8.0 作为 ［基础组件包］ 的无样式原语，不切 Radix，不混用。D13.7 的待确认项关闭。

    验证范围与证据（packages/yue/core、packages/yue/data、apps/yue-playground，CI 工作流 yue）：

    原语验证项结果
    MenuEnter 打开并聚焦首项、方向键、Enter 选中后关闭回焦、子菜单 ArrowRight / ArrowLeft、Escape、禁用项 aria-disabled、受控 open通过
    SelectArrowDown / Enter 打开 listbox、方向键高亮、Enter 选中回写、Escape 回焦、受控 value / 非受控 defaultValue通过
    Combobox输入即过滤、方向键高亮（焦点留在输入框）、Enter 选中回写、空态、Escape通过（发现 3）
    Tabstablist / tab / tabpanel 关联、roving tabindex、方向键循环、Home / End、竖向、RTL、受控 value通过（发现 2）
    TooltipTab 聚焦即显示、Escape 关闭、悬停打开、role=tooltip 与 aria-describedby通过（发现 1）
    Tree自建：方向键 / Home / End / Enter / Space、展开折叠、roving tabindex、aria-level / setsize / posinset、RTL、受控通过（发现 4）
    • 组件级：Vitest 5 浏览器模式（Playwright Chromium）21 个用例、SSR renderToString 2 个用例、门禁自测 10 个用例全部通过；每个原语打开态 axe（axe-core 4.11）critical + serious = 0，比 §4.4 的「critical = 0」更严。
    • 页面级：Playwright + @axe-core/playwright 7 个用例全部通过（整页关闭态与六个原语打开态）。
    • 无需 patch 包：下列发现全部在封装层处理。
    • 体积：靶场首屏 script 压缩后约 151 KB（预算 250 KB，PRD §14）。按源码占比：react-dom 38%、Base UI 含 floating-ui 约 36%（Combobox 7%、Select 4.6%、Menu 4.4%、Tabs 2.4%、Tooltip 1.8%）、tailwind-merge 6%。

    发现（记录为封装约定，不构成切换理由）：

    1. Tooltip 不带 ARIA 关联。Base UI 有意不输出 role="tooltip" 与 aria-describedby（把提示视为非必要的补充信息）。WAI-ARIA tooltip 模式与 PRD §07 7.15.2 的 ARIA 验收都要求这两项，封装层在打开期间补上（TooltipTrigger 的 aria-describedby 指向 TooltipContent）。
    2. Tabs 默认手动激活。方向键只移焦点、不切换；封装层默认 activateOnFocus（自动激活），需要手动激活时传 activateOnFocus={false}。禁用 tab 仍可被方向键聚焦（aria-disabled）但不激活，这是 Base UI 的可发现性策略，保留。
    3. Combobox 打开态把页面其余部分标为 aria-hidden。输入框在弹层外时 Base UI 把弹层的焦点管理设为 modal（!inputInsidePopup || modal），其余内容被标 aria-hidden 而非 inert，axe 的 aria-hidden-focus 记为 serious；弹层在焦点移出时即关闭，键盘用户不会停留在被隐藏的内容里。页面级门禁只对 Combobox 打开态豁免该规则；S1-YUE-005 评估向上游反馈或改用输入内置弹层形态。
    4. 没有 Tree 原语。Base UI 与 Radix 都没有，与路线选择无关；Tree 自建在 ［数据组件包］，用扁平 treeitem + aria-level 而非嵌套 group（嵌套会让父节点的可见文字包含整棵子树，触发 axe label-content-name-mismatch）。
    5. Base UI 要求 date-fns 作为可选 peer（只有日期类原语用到）；S1 不装，等日期族时再定。

    后续：S1-YUE-005 用 shadcn CLI 生成全集时沿用这里的封装约定（data-slot / data-testid、函数式 className 不透传、ARIA 补齐）；上述验证用例并入组件测试，不再单独维护。

    #2026-10-24 SchemaForm 校验改为解释型子集，Ajv 退为差分对照（S1-YUE-014）

    D13.2 写的「［表单组件包］ Field + SchemaForm 基于 react-hook-form + Ajv」原文不改，以此条为修订：外壳 meta CSP 不放行 'unsafe-eval'（R130 ② 登记的例外自 idadawn/qian#266 起撤销，R131），而 Ajv 在运行期用 new Function 编译 Schema，所以 ［表单组件包］ 的数据 Schema 与元数据 Schema 改由 src/json-schema.ts 解释执行。它只接受 SchemaForm 实际用到的 JSON Schema 2020-12 子集，子集内的判定、错误顺序与错误对象与此前的 Ajv 2020（allErrors、strict: false、ajv-formats full）逐条一致；子集外的断言类关键字、格式与未知关键字在渲染前拒绝，纯说明词只查参数类型（R131 ③，口径见规格 §3.3）。Ajv 从 yue-form 的运行时依赖退为开发依赖，只在差分测试里作对照；react-hook-form 不变。
