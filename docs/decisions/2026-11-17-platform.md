# 2026-11-17 平台级裁定

> 记录产品负责人 2026-11-17 对平台的裁定，引号里是原话。本文只记已定的事；待确认的事在各文档的「待定」里。

## 1 已定

| 编号 | 裁定 | 原话 |
|---|---|---|
| P1 | 总名是匠心智能体平台，不再使用 Yi。它是企业级的框架，不面向个人消费者；从拖拽式的低代码构建转为基于原生 AI、用自然语言构建系统 | 「我现在要做的事情不是一个 toC 的，它是一个企业级的框架」「基于原生 AI，可以完成基于自然语言的系统构建」「所以我把这个系统取名叫匠心智能体平台，不再使用 Yi」 |
| P2 | 平台之下三个框架：Kun；Qian，即现在的前端框架 yue；SanYuanAgent，即 iClaw 的 Python Agent 引擎，原名 NeuroAgent | 「下面包括 Kun、yue（后期改名为 Qian）、NeuroAgent……改名为 SanYuanAgent」 |
| P3 | 理念是三元全智生命体：平台（企业级框架）是三元，SanYuanAgent 是全智，平台最终演化出更多的生命体 | 「基于平台就是企业级的框架，全智是 SanYuanAgent 框架，最后平台可以进化更多的生命体」 |
| P4 | 底座不变：K8s、云原生、微服务。原来的定位没有问题，这次是拆分与聚合 | 「之前的整个框架的定位是没有问题的，只是把它做一些拆分和聚合」「以前还是太乱了，现在可能需要更多人参与或协同」 |
| P5 | 迁到 CavaiLAB 下的新仓库：一个主页仓库加各子项目，名字不带前缀，`jiangxin`、`kun`、`qian`、`sanyuan-agent`；先对内（私有）；先建仓库写框架级文档，代码之后慢慢迁。主页是 `jiangxin` 仓库的 README | 「项目需要一个 Github 项目主页+各个子项目」「先不要完全的迁移代码，先创建库吧，后期慢慢进行迁移，但是可以写文档。主要是框架级的文档」 |
| P6 | 一切皆插件是统一的原则；目标是社区里现成的开源 Agent 组件能装进平台直接用 | 「一切皆是插件 everything-is-a-plugin」 |
| P7 | 每个人有一个或多个 Agent；Agent 之间沟通的机制由平台定义；发给每个 Agent 的内容要由人审核；可以承接 iClaw 已有的实现 | 「每个人都有一个或多个 Agent」「每个 Agent 和其他 Agent 沟通的机制需要进行定义，就是发给每个 Agent 的内容需要人来进行审核」 |
| P8 | 工蜂、章蜂、群蜂对应工站、产线、工厂；SanYuanAgent 是它们的大脑，要提供给工站、产线、工厂 | 「工蜂、章蜂、群蜂 对应工站、产线、工厂」「SanYuanAgent 就是他们的大脑。需要提供给工站、产线、工厂」 |

同一天，产品负责人在来源仓库里接受了后端的合并蓝图（`idadawn/qian` 主干的 `docs/adr/ADR-023-kun-qian-merge-blueprint.md`，裁定是同仓库 `pm/tasks/S1-DEC-036.md` 的 D1–D14）：原 Qian 的后端并入 Kun，包名并为 `Kun.*`，两档分层，许可全部改 MIT，租户号用 Guid，前端由 yue 更名为 qian，运行期字面不改，按阶段落地。这些在本仓库里一律按已定写。

P1、P5 与蓝图有四处对不上。修订项登记在 `idadawn/qian` 的决策任务 S1-DEC-038（随 idadawn/qian#329 入库），待产品负责人逐项确认。

| 蓝图的条目 | 蓝图的写法 | 被哪条裁定改写 |
|---|---|---|
| 合并后的仓库（D1） | `idadawn/kun` | P5：Kun 的家是 `CavaiLAB/kun` |
| 仓库布局 | 一个仓库放下 .NET、前端、文档站、看板、契约、部署清单 | P5：前端单独一个仓库，另有总览仓库 |
| 前端包的作用域（D9） | `@idadawn/qian-<原名>` | P5：包的作用域跟着仓库所有者走 |
| 平台的名字（D8） | 平台发行版不单独起名；总名 Yi 另议 | P1：定名匠心智能体平台，不再使用 Yi |

蓝图的其余条目不受影响。逐项的提议见[仓库与归属](../05-repositories.md)第 4 节。
