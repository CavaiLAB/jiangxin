# 三种形态：从工业智能体到工业生命体

> 状态：规划稿（2026-11-17）。三种形态的划分与各自的技术架构，出自产品负责人 2026-11-17 提供的材料，第 1 至 4 节是照材料整理的。它们与三个框架的对应（第 5、6 节）是本文的展开，属于提议。

## 1 三种形态

理念里的「工蜂、章蜂、群蜂」对应工站、产线、工厂（已定）。三级各是一种智能体：

| 理念里的叫法 | 层级 | 形态 | 做什么 |
|---|---|---|---|
| 工蜂 | 工站 | 具身智能体 | 感知工件，调用技能，控制工具完成作业 |
| 章蜂 | 产线 | 协同智能体 | 协调工序、工站和物料，保持生产节拍 |
| 群蜂 | 工厂 | 超级智能体 | 协调跨系统制造任务，支撑物理 AI 研发 |

SanYuanAgent 是这三种形态的大脑，要能提供给工站、产线、工厂三级使用（已定）。

「从工业智能体走向工业生命体」是这份材料的题目。本文的理解：先有各级能独立干活的智能体，再让它们连成一体，在反馈环里自己运转、代谢和进化。生命体的含义见[理念](01-vision.md)。这个理解待产品负责人确认。

## 2 工站：具身智能体

作业智能体选择技能，具身大脑确定动作目标，工控小脑驱动本体执行并接收实测反馈。

| 层 | 做什么 |
|---|---|
| 机器人自主作业智能体 | 分解工单、编排技能，根据作业结果调整计划 |
| 具身大脑 | 融合视觉、点云和工艺信息，识别工件，生成动作目标与约束 |
| 工控小脑 | 校验运动约束，执行轨迹插补、伺服和工艺控制，反馈偏差 |
| 本体、电气与物联 | 机械臂、工具和工装执行动作，传感器、驱动和总线连接设备 |

## 3 产线：协同智能体

产线任务智能体调用专业应用，排程与孪生校核生产方案，现场控制组织多工站联动。

| 层 | 做什么 |
|---|---|
| 产线任务智能体与应用生态 | 以统一入口调用排程、质检等应用 |
| 生产调度与过程优化 | 依据工艺、物料、设备和用能约束，生成排程或运行设定值 |
| 产线数字孪生 | 根据现场数据更新工位与工序模型，校核布局、干涉和节拍 |
| 机器人自动化与工业控制 | 联动机器人、输送和公辅设施，采集实际运行状态 |

## 4 工厂：超级智能体

工厂一级的平台对外协调跨系统制造任务，对内支持物理 AI 的研发、实测与发布。

| 层 | 做什么 |
|---|---|
| 多智能体协同层 | 将任务分派给产线、机器人等智能体，协调资源冲突，按执行结果调整方案 |
| 工业数据与现场建模层 | 工业物联网接入工单与设备数据，工厂世界模型关联现场状态，调用产线孪生推演方案 |
| 物理 AI 研发底座 | 管理数据、仿真环境与算力，用实物评测验证模型和技能，发布版本及适用条件 |

## 5 与三个框架的对应

已定的有三句：SanYuanAgent 是三种形态的大脑，要提供给三级使用；它是独立运行的 SDK，每个端都要用到它，包括机器人这类边缘设备，装上就能用；模型服务由 Kun 提供，机器人本地可能还有小模型。下表是提议。

| 形态里的部分 | 提议由谁承担 |
|---|---|
| 工站的作业智能体、产线的任务智能体、工厂的多智能体协同 | SanYuanAgent。每一级最上面管「想」和「分派」的那一层 |
| 专业应用（排程、质检等）的统一入口 | Kun 的组件与能力目录：应用作为组件装进来，它的能力登记之后供智能体按权限调用 |
| 工单与设备数据的接入 | Kun 的连接器与事件 |
| 身份、权限、审计、人审 | Kun |
| 模型 | 平台的模型服务由 Kun 提供（已定）。提议：设备上的小模型由设备一侧提供，SanYuanAgent 按策略在两者之间选 |
| 各级的人机界面：工单与意图的输入、过程展示、审核 | Qian |
| 具身大脑、工控小脑、本体与电气；数字孪生、调度优化；物理 AI 研发底座 | 平台之外的专业系统，经工具、MCP 或连接器与平台往来。实时控制不经过智能体 |

## 6 云、边、端

提议：工站在端，产线在边，工厂在云。同一个引擎、同一套插件，按不同的组装部署到三处。这个对应没有经过确认。

对 SanYuanAgent 的要求随层级不同：

| 层级 | 运行环境 | 带来的要求 |
|---|---|---|
| 工站 | 贴近设备，资源受限，可能断网 | 装上就能用（已定）。提议：只装最小的一份就能运行；模型用平台的还是本机的由策略定，有本机小模型时断网退到它；与感知、控制一侧经工具或 MCP 对接 |
| 产线 | 产线一级的服务器 | 把排程、质检等专业应用当工具调用；与孪生、调度对接 |
| 工厂 | 集群 | 多智能体的分派与协同；与平台的身份、权限、审计、人审对接 |

引擎的核心现在可以脱离服务层单独安装，这是往工站一级放的基础。独立运行是什么形态、设备上的引擎怎么接平台、怎么用模型，见 SanYuanAgent 的[独立运行的 SDK](https://github.com/CavaiLAB/sanyuan-agent/blob/main/docs/sdk.md)、[接入平台：与 Kun 的交互](https://github.com/CavaiLAB/sanyuan-agent/blob/main/docs/platform.md)、[与模型服务的交互](https://github.com/CavaiLAB/sanyuan-agent/blob/main/docs/models.md)。

## 7 待定

| 事项 | 说明 |
|---|---|
| SanYuanAgent 在每一级承担到哪一层 | 第 5 节是提议。具身大脑这类感知与动作模型算不算在引擎里，待确认 |
| 三级各怎么打包与部署 | 引擎一侧已有提议，见第 6 节列出的三份文档。三级各落在云边端的哪一处、产线的边缘节点上放什么，仍然待定 |
| 三级智能体之间的任务分派要不要逐条人审 | 已定的规则是发给每个 Agent 的内容、每个 Agent 发出去的内容都要由人审核，起步两道都必审。工厂把任务分派给产线、产线分派给工站，节拍比人审快得多；是逐条审，还是由人预先批准一类任务、之后按策略放行，待定。见 [Agent 协同](04-agent-collaboration.md)第 9 节 |
| 三种形态各在路线的哪个阶段落地 | 排在里程碑 M8，见[路线](06-roadmap.md)第 2.1 节；每一级的打包与部署怎么排，见第 5 节 |
