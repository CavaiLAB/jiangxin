# 工业智能制造

> 状态：2026-11-26 重写。平台的重点是工业智能制造（已定），这一篇说车间里的系统在平台上怎么做、现在做到哪。工站、产线、工厂三级各自的技术架构（第 3 节）照产品负责人 2026-11-17 提供的材料整理；平台接到哪里（第 4 节）、设备怎么接（第 5 节）、对着哪些标准（第 6 节）是提议。标法见[平台做什么与设计理念](01-vision.md)开头。
>
> 现在仓库里工业的内容很少。已有的只有一个设备台账的样板，数据是假的；其余都是规划，各节里写明。

## 1 重点指什么

平台不仅仅面向通用办公，更深入工业智能制造，这是重点（已定）。意思是车间里的系统也按平台的办法做：人用自然语言说清要什么，智能体把它落成可运行的系统，系统上线后在人的反馈里继续改进。

和办公相比，工业现场多出几件事，平台要接得住：

| 多出来的事 | 平台怎么对 | 在哪里说 |
|---|---|---|
| 系统多，而且各管一块：设备、工艺、质量、排产、仓储 | 每个系统是平台上的一个或一组应用，用同一套登录、权限、数据、事件与审计 | 第 2 节 |
| 很多系统已经在用，不会推倒重来 | 经连接器接进来（已定） | 第 5 节，[历史系统接入](07-legacy-systems.md) |
| 现场分层：工站、产线、工厂 | 智能体分三级（已定） | 第 3 节 |
| 有设备，设备可能断网，本地可能有小模型（已定） | 设备一侧怎么接是提议，用什么运行时没有定 | 第 5 节 |
| 有实时控制 | 提议实时控制不经过智能体，留在平台之外的专业系统里 | 第 4 节 |

## 2 车间里的系统

车间里的系统，说的是设备、工艺、质量、排产、仓储这一类。产品负责人 2026-11-25 说过三个要实现的场景，第一个讲的就是它们：管理端有应用市场，里面有 MES、WMS 这样的应用；别的功能用自然语言生成，小到一张日报，大到由很多模块组成的完整应用，比如 APS；生成的应用可以上架。MES、WMS、APS 是他说场景时举的例子。

照这个场景，车间里的系统到平台上有两种来路：

| 来路 | 例子 | 靠什么 | 现状 |
|---|---|---|---|
| 做好了放进应用市场的应用 | MES、WMS | 应用也是组件：一个业务应用是一个组合包加一个市场条目，见[一切皆插件](05-plugin-model.md)第 5 节 | 组件格式、清单校验、安装已有；应用市场是规划，排在往后的那条线上（已定） |
| 用自然语言生成的应用 | 日报。先按填报的日报来排：每人每天填一张单子，主管能看、能汇总（已定） | 生成的应用是一个用数据描述的包，界面由平台的渲染器画出来（已定） | 规划，排在里程碑 M3，见[路线](13-roadmap.md)第 2.1 节 |

两种来路做出来的应用，都用企业级平台的组件来实现，这是产品负责人讲定位时的话，见[平台做什么与设计理念](01-vision.md)第 1 节；权限都走 Kun 这一套（已定）。应用之间经平台互通（已定），见[应用互通](06-app-interop.md)；那一篇第 3 节的例子就是设备点检、维修工单和消息通知三个应用配合。

生成的范围有边界。智能体生成的应用，界面只能是数据描述；需要代码时，照 Kun 现行的规格只能是沙箱里的函数。带自己逻辑的应用要等函数的沙箱，它排在往后的那条线上（已定），还没有做。

## 3 工站、产线、工厂三级

工业现场的智能体分三级：工站、产线、工厂（已定）。

| 层级 | 这一级的智能体 | 做什么 |
|---|---|---|
| 工站 | 具身智能体 | 感知工件，调用技能，控制工具完成作业 |
| 产线 | 协同智能体 | 协调工序、工站和物料，保持生产节拍 |
| 工厂 | 超级智能体 | 协调跨系统制造任务，支撑物理 AI 研发 |

三级都是规划，排在里程碑 M8。下面三张表是每一级的技术架构。

### 3.1 工站

作业智能体选择技能，具身大脑确定动作目标，工控小脑驱动本体执行并接收实测反馈。

| 层 | 做什么 |
|---|---|
| 机器人自主作业智能体 | 分解工单、编排技能，根据作业结果调整计划 |
| 具身大脑 | 融合视觉、点云和工艺信息，识别工件，生成动作目标与约束 |
| 工控小脑 | 校验运动约束，执行轨迹插补、伺服和工艺控制，反馈偏差 |
| 本体、电气与物联 | 机械臂、工具和工装执行动作，传感器、驱动和总线连接设备 |

### 3.2 产线

产线任务智能体调用专业应用，排程与孪生校核生产方案，现场控制组织多工站联动。

| 层 | 做什么 |
|---|---|
| 产线任务智能体与应用生态 | 以统一入口调用排程、质检等应用 |
| 生产调度与过程优化 | 依据工艺、物料、设备和用能约束，生成排程或运行设定值 |
| 产线数字孪生 | 根据现场数据更新工位与工序模型，校核布局、干涉和节拍 |
| 机器人自动化与工业控制 | 联动机器人、输送和公辅设施，采集实际运行状态 |

### 3.3 工厂

工厂一级的平台对外协调跨系统制造任务，对内支持物理 AI 的研发、实测与发布。

| 层 | 做什么 |
|---|---|
| 多智能体协同层 | 将任务分派给产线、机器人等智能体，协调资源冲突，按执行结果调整方案 |
| 工业数据与现场建模层 | 工业物联网接入工单与设备数据，工厂世界模型关联现场状态，调用产线孪生推演方案 |
| 物理 AI 研发底座 | 管理数据、仿真环境与算力，用实物评测验证模型和技能，发布版本及适用条件 |

## 4 平台接到哪里

提议。上面三张表里，平台承担的是每一级最上面的那一层，以及它要用到的身份、权限、数据与模型；其余是平台之外的专业系统。

| 三级里的部分 | 提议由谁承担 | 依据与现状 |
|---|---|---|
| 工站的作业智能体、产线的任务智能体、工厂的多智能体协同：每一级管「想」和「分派」的那一层 | Agent | 平台现在的 Agent 运行时是 DSH（已定），跑在服务器和各人的电脑上。工站、产线的设备上用什么运行时，没有定 |
| 排程、质检等专业应用的统一入口 | Kun 的组件与能力目录：应用作为组件装进来，它的能力登记之后供智能体按权限调用 | 能力目录已有；智能体按权限调用要等智能体主体，排在里程碑 M1 |
| 工单与设备数据的接入 | 连接器与事件 | 事件已有；连接器是规划 |
| 身份、权限、审计、人审 | Kun | 权限统一走 Kun 已定；人审的规则已定，实现是规划 |
| 模型 | 平台的模型服务由 Kun 提供；机器人这类设备本地可能还有小模型（已定） | 模型服务的接口是规划；设备上的本机模型等设备一侧的运行时定下来再定 |
| 各级的人机界面：工单与要求的输入、过程展示、审核 | 匠心：Agent 工作区与管理端 | 界面不由 Kun 承担已定，现在放匠心；这些界面都是规划 |
| 具身大脑、工控小脑、本体与电气；数字孪生、调度优化；物理 AI 研发底座 | 平台之外的专业系统，经工具、MCP 或连接器与平台往来。实时控制不经过智能体 | 提议 |

## 5 设备与历史系统怎么接

**历史系统。** 车间里已有的系统经连接器接进来：一套系统一个连接器，把它翻译成平台的能力、事件与数据；历史系统在企业内网的，连接器的执行部分装在内网，只向外连（已定）。做法见[历史系统接入](07-legacy-systems.md)。

**设备。** 设备一侧用什么运行时，没有定。下面几条是此前的提议，说的是设备上的 Agent 怎么和平台往来，不依赖用哪个运行时；运行时定下来以后要重看。

- **只向外连，只认一个入口地址。** 设备多半在车间网络里，外面连不进来。
- **入网要人批准。** 在本机生成密钥，由主人本人在平台上批准，之后用设备密钥换短期的令牌。
- **断网尽量不停工。** 设备上有本机模型时，断网后本机该干的活照干，按缓存的策略行事；审计与用量先存本机，联网后补传。没有本机模型的设备，断网后做不了新的推理。
- **模型两头都能用。** 平台的模型经平台的模型服务调用，由平台计量；本机小模型不经过平台，用量由设备一侧上报。标了不得离开设备的内容只走本机。

三级各放在哪也是提议：工站的在设备上，产线的在产线一级的服务器上，工厂的在集群里。这个对应没有经过确认。

## 6 对着哪些工业标准

代码要符合 ISO 等国际相关标准（已定）。对着哪些标准、各做到哪一步，写在[遵循的标准](12-standards.md)。清单是提议，没有逐项定。

和工业直接有关的，这里只点名：

- 数据模型、指标、设备接入、批控制：IEC 62264（ISA-95）、ISO 22400、IEC 62541（OPC UA）、IEC 61512。
- 工业场景下的安全开发：IEC 62443-4-1、IEC 62443-4-2。
