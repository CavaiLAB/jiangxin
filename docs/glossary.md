# 术语与名称对照

> 状态：规划稿（2026-11-17）。

## 1 名字换了什么

2026-11-17 起，几个名字的所指变了。读旧文档之前先看这张表。

| 名字 | 以前指什么 | 现在指什么 | 什么时候生效 |
|---|---|---|---|
| 匠心智能体平台 | — | 整个平台的名字 | 2026-11-17 |
| Yi（易） | 2026-11-11 定的产品族总名 | 不再使用 | 2026-11-17 |
| Kun | .NET 云原生微服务框架，包名 `Kun.*` | 为 Agent 时代构建的多租户平台框架：原 Kun 加上原 Qian 的后端，包名统一为 `Kun.*` | 定位已定；代码归并在阶段 3 |
| Qian | 基于 Kun 的平台层：`Qian.*` 包、平台插件 | 只作前端框架的名字，也就是原来的 yue | 更名排在阶段 3 的最后一批。在那之前，原仓库里的 Qian 仍是旧含义 |
| yue | 前端组件库与外壳 | 过渡期的名字，将更名为 Qian | 阶段 3 的最后一批 |
| NeuroAgent | iClaw 的 Python Agent 引擎 | 改名 SanYuanAgent | 阶段 2 |
| SanYuanAgent | — | 智能体引擎 | 2026-11-17 |

读旧文档时注意：写于 2026-11-17 之前的文档里，「Qian」指平台层；「三层口径」指 Kun 框架层、Qian 平台层、yue 前端层。

**保留不改的 `qian` 字面。** 组件 id 的前缀 `qian.`、清单与配置的文件名（`.qian-plugin/plugin.json`、`qian.profile.yml`、`qian.patch.yml`）、`qian` 命令行、`@qian/*` 的导入名，这次都不改。它们已经落库、上线或冻结，改动的代价大而不带来功能。今后它们只是历史字面，不表示产品名，也不表示前端框架。

## 2 理念

| 术语 | 含义 |
|---|---|
| 三元全智生命体 | 平台的设计理念。三元给躯体，全智给心智，生命体给活法 |
| 三元 | 结构怎么融合：云边端；工蜂、章蜂、群蜂；人机物。在平台里对应底座 Kun 与 Qian |
| 全智 | 智能到什么水平。在平台里对应 SanYuanAgent |
| 生命体 | 平台上长出来的系统与智能体的组合，在反馈环里运转并改进 |
| 反馈环 | 人的意图与判断 → 系统的理解与决策 → 环境被行动改变 → 结果成为反馈与记忆 → 回到人 |
| 自然语言构建 | 人用自然语言描述意图，智能体生成或修改声明式表面，经校验和人工批准后上线 |

## 3 平台术语

| 术语 | 含义 |
|---|---|
| 组件 | 一个文件夹加一份清单、若干声明式表面和可选的代码；分发与安装的单位 |
| 插件 | 组件的运行时形态：挂进共享上下文，贡献服务、监听器和可撤销的副作用 |
| 表面 | 组件向外暴露的一类声明式内容：技能、子 Agent、命令、钩子、MCP 服务器、工具、界面、元数据、业务元数据、配置补丁 |
| 清单 | 组件根目录下描述它的那份 JSON 文件 |
| 能力的三个角色 | 定义（接口与词汇）、提供方（实现）、消费方。消费方只依赖定义 |
| 范围 | 一项注册的归属：全局，或者恰好一个租户、应用或 Agent 会话 |
| profile | 一份具名的插件组装，也是一个可部署单元 |
| 组合包 | 带着一组配置条目的组件，被 profile 引用时整层叠加 |
| 补丁 | 对插件树里某个条目的替换、禁用或插入 |
| 插件树 | 由 profile、组合包和各层补丁叠出来的全部条目 |
| 目录市场 | git 仓库里的一份清单文件，列出可以安装的组件及其来源 |
| 信任等级 | 组件的来源等级，决定它能带什么形态的代码、在哪里运行 |
| 主体 | 行事的一方：`user`（人）、`service`（服务）、`agent`（智能体） |
| 委托链 | 令牌里写明「谁代表谁行事」的一串记录 |
| 能力目录 | 平台全部能力的登记：输入输出 Schema、副作用等级、所需权限、是否对 Agent 暴露 |
| 强制执行点 | 每次能力调用必经的权限判定位置 |
| 协同消息 | Agent 与 Agent 之间往来的消息，经平台的信箱转交 |
| 人审 | 人对协同消息、智能体生成的变更或高风险动作做批准、修改或驳回 |
