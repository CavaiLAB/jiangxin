    #匠心工业智能体平台

    企业级的 AI 原生平台。人用自然语言说清要什么，智能体把它落成可运行的系统；系统上线后在人的反馈里继续改进。

    平台面向组织，不面向个人消费者。它不只做通用办公，重点是工业智能制造：设备、工艺、质量、排产、仓储这些车间里的系统，也这样说出来、搭起来、改下去。

    平台由两部分组成：

    • 匠心（本仓库）：产品。Agent 工作区（Web 端与桌面端，基于 DSH 构建）、管理端、产品的插件，以及部署清单。登录、工作区和管理端等产品页面都放在这里重新设计。
    • Kun：企业级框架。登录、权限、多租户、数据、事件、审计、模型服务的接口，都以插件的形式装配。平台上做的每一个系统，权限都走它这一套。它保持现有基础框架和接口，继续负责认证、会话和权限。

    部署有两种形态：带模型推理的集群（推理服务用 GPUStack）；不带推理、通过 API 接第三方的模型服务。提供多租户和单租户两个版本。不管哪一种，统一由管理端管理。先交付两套：企业版，集群、多租户、带推理；单机版，一台服务器、单租户、不带推理。整个平台只有一个 Kun 模型服务，两套共用。

    状态（2026-11-27）。 上面几段照产品负责人 2026-11-26 定的方向写，2026-11-27 跟上了他对待定事项的两次答复和产品页面的新方向；各篇里标着哪些已定。做到哪一步见下面的现状：管理端、模型服务的接口、两套部署的装配都还没有实现。文档里标「已定」的是已经裁定的事，标「提议」「待定」的还没有拍板，标「延期」的是定了先放着、写明了要先有什么的事，标「按提议推进」的是定了到时候照提议做的事，标「带条件」的是定了条件、要看条件满不满足的事；说现状时，「已有」指已经实现，「规划」指还没有实现。

    #平台做什么

    过去企业搭业务系统的省力办法是低代码或无代码平台：把系统拆成表单、列表、流程这些可配置的元数据，由人在设计器里拖拽出来。匠心保留「系统由声明式元数据描述」这一点，把写元数据的人换成智能体。人负责提出要求、判断结果对不对，智能体负责理解、生成和执行。按设计，每一步都受权限、审计和人工审核约束。

    展开见平台做什么与设计理念；工业这一块见工业智能制造，第一个工业参考应用做生产日报的填报，再接到排产（已定）。

    #各部分管什么

    部分是什么在哪里
    匠心产品：Agent 工作区的 Web 端与桌面端、管理端、产品的插件、部署清单本仓库
    Kun企业级框架，.NET 10：登录、权限、多租户、数据、事件、审计、模型服务的接口，以插件的形式装配CavaiLAB/kun
    DSH上游的 Agent 运行时，界面外壳也用它自己的客户端。我们钉死版本，不改它的源码以 npm 包装进本仓库的发行目录
    • 人用平台，入口是 Agent 工作区；管理端是另一块，给很多人用，不需要 DSH 实例。见产品形态。
    • 登录、工作区和管理端等产品页面统一放到匠心重新设计，旧布局和样式可以淘汰；页面由匠心出，认证、会话和权限的接口由 Kun 出（已定）。匠心根据工业填报、管理和 Agent 工作区的实际场景制定自己的设计规范，Ant Design 仅供参考（已定）；现在只有底稿，见设计规范。次序是先列清各个包的去向，再修订文档，再用登录页跑通前后端流程（已定），见包与应用的去向与路线第 2.4 节。
    • 前后端都要有面向开发者和 Agent 的文档、MCP 和 CLI 入口，让人能找到匠心组件、Kun 接口和可运行的示例（已定）。现在有什么、缺什么，见在平台上做开发第 10 节。
    • 平台上不论做什么系统，权限都走 Kun 这一套；模型服务由 Kun 提供，留一套标准的接口，整个平台只有这一个模型服务。见总体架构。
    • Kun 的文档在它自己的仓库里。Kun 要有单独的网站，放使用文档和给大模型用的文档（已定）；网站的域名定为 kun.2017601.xyz（已定）。公网入口、证书和站点内容验收通过以后，再把指向 Kun 文档的链接切到网站上。
    • 现在只剩两个项目：匠心与 Kun（已定）。前端框架 Qian 的仓库已归档，已发布的包留着；SanYuanAgent 的仓库保留，暂不维护。

    #现状

    本仓库里现在有的东西都在仓库根下，都还没有发布过。各目录怎么用，看它自己的 README。

    目录放什么状态
    distribution/发行目录：钉死版本的 DSH（0.2.2-rc.5）、以 tarball 装入的品牌包与插件包、按文件名叠加的配置补丁、启动器和启动前检查。Web 端和桌面端共用已有
    apps/web/Web 端：启动脚本，放在反向代理后面的配置与验证已有：本机能起一个单人的实例，用假模型。按人托管是规划
    apps/desktop/桌面端：一个薄的 Electron 壳，里面跑发行目录里的 DSH已有：原型
    apps/console/管理端规划。现在只有说明
    packages/品牌包 @jx/brand-theme；企业插件的样板 @jx/enterprise-workbench，数据是假的；界面组件包 @jx/ui-kit已有
    tests/egress/外联检查：在不通外网的容器网络里看实例想连哪些地址已有
    tools/mock-model/本机的假模型服务，本机试用和测试不需要真的模型与密钥已有
    patches/对 DSH 源码的改动，一处一个补丁文件只有两个样例，没有用于任何构建
    contracts/以后从 Kun 的契约生成的类型空的，占位
    brand/匠心 logo 的原图，不在任何代码许可之内已有
    deploy/产品的部署清单规划。目录还没有建
    website/文档站已有
    docs/平台的文档，见下面的文档—

    还没有的，都是规划：

    • 匠心自己的认证页（登录、选择租户等）；管理端；把登录的人送进他自己实例的工作区服务，和按人托管的 DSH 实例。
    • 设计规范的定稿；面向开发者和 Agent 的 MCP 与命令行入口。
    • 对话里的确认卡与「待确认」的页面。
    • 用自然语言生成应用。
    • Kun 一侧的模型服务的接口、远程的授权接口、智能体主体。
    • 企业版与单机版两套各自的装配，和产品的部署清单。

    先做什么、后做什么，见路线。Kun 的发布情况与安装入口，见 Kun 的仓库。
